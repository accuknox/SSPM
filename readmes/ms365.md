## Prerequisites

- **Python 3.11+** and the `accuknox-sspm` package installed:
  ```bash
  pip install accuknox-sspm
  # or development install from source
  pip install -e .
  ```
- A **Microsoft 365 tenant** with a **Global Administrator** or **Privileged Role Administrator** account to create the app registration and grant admin consent.

---

## Setting Up Credentials

The scanner authenticates using **app-only (client credentials) flow** — no user login or MFA prompt is required during the scan.

---

### Step 1 – Create an App Registration

1. Sign in to the [Azure Portal](https://portal.azure.com) as a **Global Administrator**.
2. Navigate to **Microsoft Entra ID → App registrations → New registration**.
3. Fill in the form:
   - **Name**: `accuknox-sspm` (or any descriptive name)
   - **Supported account types**: Accounts in this organizational directory only (single tenant)
   - **Redirect URI**: Leave blank
4. Click **Register**.
5. On the app overview page, copy and save:
   - **Application (client) ID** → used as `--client-id`
   - **Directory (tenant) ID** → used as `--tenant-id`

---

### Step 2 – Create a Client Secret

1. In the app registration, go to **Certificates & secrets → Client secrets → New client secret**.
2. Add a description (e.g. `sspm-scanner-secret`) and choose an expiry (24 months recommended).
3. Click **Add**.
4. **Copy the secret Value immediately** — it is shown only once and is used as `--client-secret`.

> Store this secret in a secrets manager (Azure Key Vault, GitHub Actions secrets, etc.). Never commit it to source control.

---

### Step 3 – Add Microsoft Graph API Permissions

1. In the app registration, go to **API permissions → Add a permission → Microsoft Graph → Application permissions**.
2. Search for and add each of the following permissions:

| Permission | Purpose |
|---|---|
| `Organization.Read.All` | Tenant organization info and branding |
| `Domain.Read.All` | Verified domain list |
| `User.Read.All` | User accounts and properties |
| `Group.Read.All` | Microsoft 365 and security groups |
| `Directory.Read.All` | Directory roles and role members |
| `Policy.Read.All` | Conditional Access, auth methods, authorization, timeout, device registration, cross-tenant policies |
| `RoleManagement.Read.Directory` | PIM role assignments and eligibility schedules, role management policies |
| `AuditLog.Read.All` | Sign-in logs (audit log status probe) |
| `Reports.Read.All` | Per-user MFA registration details |
| `InformationProtectionPolicy.Read.All` | Sensitivity labels / DLP policies |
| `DeviceManagementConfiguration.Read.All` | Intune device compliance policies |
| `DeviceManagementServiceConfig.Read.All` | Intune enrollment restrictions |
| `SharePointTenantSettings.Read.All` | SharePoint tenant-level settings |
| `AccessReview.Read.All` | Identity Governance access review definitions |

3. After adding all permissions, click **Add permissions** to confirm.

---

### Step 4 – Grant Admin Consent

All permissions above are **Application** permissions that require admin consent before they can be used.

1. In **API permissions**, click **Grant admin consent for \<Your Tenant\>**.
2. Click **Yes** to confirm.
3. All permissions should now show a green **Granted** checkmark.

> Only a **Global Administrator** or **Privileged Role Administrator** can grant admin consent.

---

### Step 5 – Collect the Required IDs

You need three values to run the scan:

| Value | Where to find it |
|---|---|
| **Tenant ID** | App registration overview → Directory (tenant) ID |
| **Client ID** | App registration overview → Application (client) ID |
| **Client Secret** | Copied in Step 2 (cannot be retrieved again) |
| **Tenant Domain** *(optional)* | Your primary `.onmicrosoft.com` domain or custom domain |

---

### Step 6 – Verify Access

Test that authentication works before running a full scan:

```bash
# Set credentials as environment variables
export SSPM_TENANT_ID=<your-tenant-id>
export SSPM_CLIENT_ID=<your-client-id>
export SSPM_CLIENT_SECRET=<your-client-secret>

# Quick connectivity test (lists a single user)
curl -s -X POST \
  "https://login.microsoftonline.com/${SSPM_TENANT_ID}/oauth2/v2.0/token" \
  -d "grant_type=client_credentials" \
  -d "client_id=${SSPM_CLIENT_ID}" \
  -d "client_secret=${SSPM_CLIENT_SECRET}" \
  -d "scope=https://graph.microsoft.com/.default" \
  | python3 -c "import sys,json; d=json.load(sys.stdin); print('OK –', d.get('token_type','ERROR'))"
```

Expected output: `OK – Bearer`

All permissions are **Microsoft Graph Application permissions** — they operate without a signed-in user and require admin consent.

```

User.Read.All
Group.Read.All
Directory.Read.All
Policy.Read.All
RoleManagement.Read.Directory
AuditLog.Read.All
Reports.Read.All
InformationProtectionPolicy.Read.All
DeviceManagementConfiguration.Read.All
DeviceManagementServiceConfig.Read.All
SharePointTenantSettings.Read.All

```

> **Note:** Some controls (Defender Safe Links/Attachments, Exchange transport rules, Microsoft Fabric) cannot be collected via Microsoft Graph. Rules for those controls return a `MANUAL` finding pointing the auditor to the relevant admin console.

## CLI Reference

```
sspm scan ms365 [OPTIONS]
```

| Option | Env Variable | Required | Description |
|--------|-------------|----------|-------------|
| `--tenant-id TEXT` | `SSPM_TENANT_ID` | Yes | Entra ID tenant GUID |
| `--client-id TEXT` | `SSPM_CLIENT_ID` | Yes | App registration client ID |
| `--client-secret TEXT` | `SSPM_CLIENT_SECRET` | Yes | App registration client secret |
| `--tenant-domain TEXT` | `SSPM_TENANT_DOMAIN` | No | Human-readable domain label (e.g. `contoso.onmicrosoft.com`) used in report titles |
| `--profile TEXT` | — | No | Limit scan to a CIS profile: `"E3 Level 1"`, `"E3 Level 2"`, `"E5 Level 1"`, or `"E5 Level 2"` |
| `--rule TEXT` | — | No | Limit scan to one or more specific rule IDs (repeatable) |
| `--output TEXT / -o` | — | No | Output file stem (default: `sspm-ms365-report`). Generates `<stem>.html` and `<stem>.sarif.json` |
| `--no-html` | — | No | Skip HTML report generation |
| `--no-sarif` | — | No | Skip SARIF report generation |
| `--verbose / -v` | — | No | Print individual findings to the terminal during the scan |

## Usage Examples

### Basic scan with explicit credentials

```bash
sspm scan ms365 \
  --tenant-id     xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx \
  --client-id     yyyyyyyy-yyyy-yyyy-yyyy-yyyyyyyyyyyy \
  --client-secret "your-client-secret-here" \
  --tenant-domain contoso.onmicrosoft.com \
  --output contoso-cis-report
```

### Scan using environment variables (CI/CD)

```bash
export SSPM_TENANT_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
export SSPM_CLIENT_ID=yyyyyyyy-yyyy-yyyy-yyyy-yyyyyyyyyyyy
export SSPM_CLIENT_SECRET=your-client-secret-here
export SSPM_TENANT_DOMAIN=contoso.onmicrosoft.com

sspm scan ms365 --output contoso-report --verbose
```

### E3 Level 1 controls only

```bash
sspm scan ms365 \
  --tenant-id     $SSPM_TENANT_ID \
  --client-id     $SSPM_CLIENT_ID \
  --client-secret $SSPM_CLIENT_SECRET \
  --profile "E3 Level 1" \
  --output e3-l1-report
```

### Run a single rule

```bash
sspm scan ms365 \
  --tenant-id $SSPM_TENANT_ID \
  --client-id $SSPM_CLIENT_ID \
  --client-secret $SSPM_CLIENT_SECRET \
  --rule ms365-cis-5.1.2.1
```

### SARIF output only

```bash
sspm scan ms365 \
  --tenant-id     $SSPM_TENANT_ID \
  --client-id     $SSPM_CLIENT_ID \
  --client-secret $SSPM_CLIENT_SECRET \
  --no-html \
  --output ms365-sarif-only
```

### List all MS365 rules (without scanning)

```bash
sspm rules list --provider ms365
```

## Output Files

Running `sspm scan ms365` produces two files by default:

| File | Format | Description |
|------|--------|-------------|
| `sspm-ms365-report.html` | HTML | Interactive report with summary dashboard, per-rule findings, remediation steps, and evidence |
| `sspm-ms365-report.sarif.json` | SARIF 2.1.0 | Machine-readable findings compatible with GitHub Advanced Security, VS Code SARIF Viewer, and any SARIF-aware toolchain |

### Finding statuses in the report

| Status | Meaning |
|--------|---------|
| `PASS` | Control is compliant |
| `FAIL` | Control is non-compliant; remediation required |
| `MANUAL` | Cannot be automated; human review required (e.g. Defender, Exchange, Fabric settings) |
| `SKIPPED` | Prerequisites not met |
| `ERROR` | Unexpected error during rule evaluation |

## Security Recommendations

- **Use a dedicated app registration.** Do not reuse an existing application — create one specifically for scanning so it can be disabled or deleted independently.

- **Apply least-privilege permissions.** The permissions listed above are the minimum required. Do not add `Write`, `ReadWrite`, or `FullControl` permissions.

- **Rotate the client secret.** Set a calendar reminder before the secret expires. Generating a new secret does not invalidate the old one — you can rotate with zero downtime by creating a second secret, updating the scan config, then deleting the old secret.

- **Store the secret securely.**
  - Local use: environment variable or a `.env` file with `chmod 600`, never in source control.
  - CI/CD: use your platform's secrets manager (GitHub Actions secrets, Azure Key Vault, HashiCorp Vault).

- **Monitor app activity.** The app registration appears in Microsoft Entra sign-in logs. Review it periodically for unexpected authentication events.

- **Restrict by IP (optional).** You can add a Conditional Access policy that restricts the app to specific IP ranges, though this requires an Entra ID P1 or P2 license.
